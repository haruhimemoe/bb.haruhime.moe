# AGENTS.md

Rules for any agent (or human) working in this repo. Authoritative; `CLAUDE.md` only layers on top.

## 1. What this is

bb.haruhime.moe is an osu! BBCode editor with a live preview, plus templates: built-in ones (in the repo), people's own, and a public gallery. Anyone signs in with osu! to make, fork and report templates; admins clear reports. The binding spec is the vault note `05 - Notes/Projects/bb.haruhime.moe/Docs/Specs/2026-09-28-bb-design.md` (section 2). This stage is the app skeleton and the accounts and templates backend; the CodeMirror editor, `/docs`, flags, colors, the collab maker and pool import come next, on `@haruhimemoe/bbcode`.

**Hard rule: we never host images.** No image, audio or video bytes pass through or are stored by our code. Templates hold URLs only; previews load them in the browser from their host. The CSP in `next.config.ts` opens `img-src` to `https:` and `media-src` to `https:` for that, and allows only YouTube's embed as a frame (`tests/unit/config/headers.test.ts`).

## 2. Layout

```
src/app/            routes only (thin; compose components)
src/components/     feature folders (account/, admin/, auth/, editor/, layout/, me/, templates/); primitives come from @haruhimemoe/ui
src/hooks/          client hooks (useDraft: the editor's text in localStorage)
src/constants/      static data (site, legal, db names, api limits, templates, editor)
src/utils/          pure, stateless helpers (ids, access rules, fill, front matter, gallery params, storage, llms.txt)
src/lib/            integration plumbing wired from @haruhimemoe/next-kit (db, auth, rate limits, route guards),
                    the render seam (bbcode.ts) and the built-in template loader
src/services/       database work (templates create/read/update, gallery, reports, uses, account)
src/models/         the templates collection's Mongoose schema and indexes; typed driver collections
src/schemas/        zod schemas and shared types (template, fields, text rules, views, session user)

content/templates/  built-in templates, one `.bb` file each with front matter
public/brand/       logos, icon and palette generated by @haruhimemoe/brand (`bunx haruhime-brand bb`; never edited by hand)
tests/              unit/ (node), components/ (jsdom), integration/ (node + in-memory Mongo), helpers/, setup/
llms.txt            the repo's own llms.txt; the site's is built by src/utils/llms-txt.ts
```

## 3. Code style

- TypeScript 7, `strict`, `noUncheckedIndexedAccess`. No `any`; validate external data with zod.
- Biome is the only linter and formatter (`bun run check`, `bun run check:fix`).
- No barrel files in `src/`. Import exact local paths. npm packages are imported from their published entry points.
- One component per file, PascalCase filename, Tailwind only. A component file exports only components and their prop types: copy goes in `src/constants/`, helpers in `src/utils/`.
- Take what the shared packages have instead of copying it: server plumbing from `@haruhimemoe/next-kit` (route helpers, rate limits, env, MongoDB and its indexes, osu! sign-in and the account store), wired once in `src/lib/api.ts`, `rate-limit.ts`, `db.ts`, `db-indexes.ts`, `auth.ts`, `account.ts`, `template-routes.ts` and `src/env.ts`; UI pieces from `@haruhimemoe/ui`; the content filter from `@haruhimemoe/pool/content-filter`; osu! links from `@haruhimemoe/osu/shapes`. A component ui lacks goes in `src/components/` and is noted as a ui candidate.
- Files stay under about 250 lines and components under about 200 (`tests/unit/tooling/file-size.test.ts`). No import cycles in `src/`.
- `utils/` is pure. Server-only modules `import "server-only"`. Client code never imports the `@haruhimemoe/osu` root (it holds the osu! secret; `tests/unit/tooling/client-imports.test.ts`).
- Rendered BBCode reaches the DOM only through `BbPreview`, which only renders `renderBbcode` from `src/lib/bbcode.ts`. Nothing else uses `dangerouslySetInnerHTML`.

## 4. File headers

Every `.ts`, `.tsx`, `.mjs`, and `.css` source file starts with:

```ts
/**
 * @file <repo-relative path>
 * @desc <what it is and why>
 * @author David @dvhsh (https://dvh.sh)
 * @created Ddd MMM D, YYYY
 * @modified Ddd MMM D, YYYY
 */
```

Dates match `date "+%a %b %-d, %Y"`. Update `@modified` on edits, never `@created`. Every export gets a doc comment right above it (one line is enough for a constant, type or schema); exported functions, components and route handlers get a JSDoc block with `@function`, `@param`, `@returns` (and `@throws` when they throw). `tests/unit/tooling/jsdoc.test.ts` checks every header and comment. Route files export only route handlers and Next's route options.

## 5. Tests

- Everything under `tests/`, mirroring `src/` paths. Write the failing test first.
- `bun run test` runs all three Vitest projects. The unit project runs with `TZ=America/Los_Angeles` on purpose.
- Tests never reach the network: msw (`setupMsw` from `@haruhimemoe/next-kit/testing`, `onUnhandledRequest: "error"`) for osu! and pools once features call them. The fake env is next-kit's `stubOsuAppEnv`; the in-memory MongoDB is its `startMemoryMongo` (`tests/setup/integration-global.ts`).
- Integration tests use `setupTestDb()` (`tests/helpers/db.ts`), build rows with `makeTemplate` / `insertTemplate` and bodies with `validBody` (`tests/helpers/templates.ts`), and sessions with `createCast()` (owner, admin, other; `tests/helpers/requests.ts`). Every API route has a test for its permissions.
- Coverage floor: 90% on `src/utils/**` and `src/schemas/**`.

## 6. Visual system

osu!-web look from `@haruhimemoe/ui`: `src/app/globals.css` imports its theme and pins `--hue: 265` (bb's violet) and `--h2-l: 45%`. Dark only. Font: Nunito. Page titles go through `PageHeader`. The preview's placeholder class `.bb-source` lives in `globals.css` until `@haruhimemoe/bbcode/styles.css` replaces it.

## 7. Legal copy and docs

- Legal pages are `content/legal/*.mdx`, registered in `src/constants/legal.ts`; bump `lastUpdated` with any wording change.
- A new per-IP or per-account counter, or anything new we store, goes in `privacy.mdx`.
- A change people see updates the README's Features and, when it adds a page, `src/utils/llms-txt.ts` and the sitemap.
- No em dashes in any copy (`tests/unit/content/copy-rules.test.ts`). osu! wiki text is CC BY-NC and osu-web is AGPL: write from observed behavior, never copy.

## 8. Commits and PRs

- Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `test:`, `refactor:`).
- Before pushing: `bun run check && bun run typecheck && bun run test && SKIP_ENV_VALIDATION=true bun run build`.
- When a change affects conventions, update this file in the same PR.

## 9. Templates

- The database is always `bb` (`DB_NAME` in `src/lib/db.ts`). Server env comes from `src/env.ts` only; `ADMIN_OSU_IDS` is read on every call. Never print a secret; never read `.env.local` in a tool call.
- `templates` (`src/models/Template.ts`, `src/schemas/template.ts`): `{ _id: "t-xxxxxxxx", ownerOsuId, ownerName, name (3..80), description (0..280), kind, body (1..60,000), fields[], visibility: private | unlisted | public, forkOf (id or null), uses, reports, hidden, createdAt, updatedAt, version }`. Indexes: owner with updatedAt, visibility with updatedAt (Newest), visibility with uses (Most used), a text index on name and description (search), hidden. Ids are drawn by `newTemplateId` and drawn again on a clash.
- Fields (`src/schemas/template-field.ts`): `{ key, label, kind: text | multiline | number | date | url | user | users | country | color, required, default }`, keys unique, at most 40. Placeholders are `{{key}}`.
- Every typed text (name, description, body, field labels and defaults) goes through the content filter on writes (`src/schemas/text.ts`; refusal code `content_filter`). Reads use `templateReadSchema`, shape only, so a template a newer filter refuses still reads, can be renamed and deleted; a fork of it is refused until it passes.
- Who may do what is `src/utils/template-access.ts`: the owner everything; anyone sees unlisted and public templates that aren't hidden; admins also see hidden ones and never edit; can't see it 404, signed out on a write 401, sees it but may not 403. Built-in templates are 403 for edits, deletes and reports.
- Writes go through `src/lib/template-routes.ts`: session, `refuseCrossSite`, a strict JSON body of at most 512 KB, then a per-user limit keyed `osu:<osuId>` (next-kit's `userSubject`): `templateWrites` 30 a minute (create, edit, fork, delete), `templateReports` 10 an hour, `accountDelete` 3 an hour. "Use" (`POST /api/templates/<id>/use`) needs no session, is same-site only and counts 30 an hour per IP.
- Changes are versioned: `PATCH` carries `baseVersion`; one guarded `findOneAndUpdate` matches it and bumps it; a mismatch is 409 with the current template (`template` in the answer), which the form takes and says so.
- Each account owns at most 100 templates: counted before the insert and again after it, which backs out when over.
- Reports (`template_reports`: `{ templateId, reporterOsuId, reason, at }`, unique on template and reporter): each bumps `reports`; a public template at 3 is `hidden` (also when it becomes public with 3). Hidden stays set until an admin clears it (`DELETE /api/admin/templates/<id>/reports`: `reports` 0, `hidden` false, report rows kept so the same people can't report again). Admin routes answer 404 to everyone else first. `/admin` lists reported templates.
- Built-in templates are `content/templates/*.bb`: front matter (`name`, `kind`, `description`, `fields`, the small YAML subset `src/utils/front-matter.ts` reads) and the body, checked with the same content schema. Their id is `bb-<file name>`; their uses live in `builtin_template_uses`. They show on page 1 of the gallery marked "Built in", can be used and forked, never edited or reported. `tests/unit/content/builtin-templates.test.ts` checks every placeholder is declared and only osu! tags are used.
- The gallery, sitemap and llms.txt list public templates that aren't hidden; under `SKIP_ENV_VALIDATION` their database lists are empty. Counts run as the `count` command, not an aggregation.
- Deleting an account deletes its templates, their reports, the reports it filed, its sessions, linked accounts and user (`src/services/account.ts`).

## 10. Seams for `@haruhimemoe/bbcode`

- `src/lib/bbcode.ts`: `renderBbcode(text)` (safe HTML) and `countBbcode(text)`. Today it escapes the source into `<pre class="bb-source">`; swap the bodies for the package's `render` and `count`. Callers: `BbPreview`, `EditorShell`.
- `src/utils/template-fill.ts`: `fillTemplate(body, fields, values)` and `templateFields(body, fields)` under the names `@haruhimemoe/bbcode/template` exports; swap the implementation for re-exports. `formatValue` wraps `user` and `users` in `[profile]` and upper-cases `country`; keep that or move it to the package.
- `src/components/editor/EditorShell.tsx` is the textarea placeholder the CodeMirror editor replaces; `useDraft` keeps one draft under `bb:draft` and takes the "Use" hand-off under `bb:handoff`.
